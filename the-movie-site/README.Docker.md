# the-movie-site Deployment Guide

An optimized, secure Docker deployment configuration for **the-movie-site** utilizing Next.js Standalone mode. This setup guarantees minimal production image sizes, non-root execution safety, and modular developer workflows.

---

## One-Shot Local Testing

Run this combined command chain to build and launch **the-movie-site**. The second the server is stopped using `Ctrl + C`, a cleanup sequence triggers automatically to permanently erase the temporary image and all intermediate build caches from the hard drive:

```bash
chmod +x docker-run-clean.sh
./docker-run-clean.sh
```

---

## Targeted Development & Clean-Up Workflow

Use these targeted instructions to test changes locally and erase _only_ the footprints generated by **the-movie-site** without wiping other active Docker projects on the system.

### 1. Build the isolated image

```bash
docker build --no-cache -t the-movie-site:latest .
```

### 2. Run the container

The `--rm` flag guarantees that container logs and temporary runtime configurations self-destruct the second the server is stopped.

```bash
docker run --rm -p 6969:6969 --name movie-site-instance the-movie-site:latest
```

### 3. Target and Erase Project Footprints

Once testing is finished, execute these commands to drop the running container, delete the compiled production layers, and purge the isolated project caches:

```bash
# Stop the running application instance
docker stop movie-site-instance

# Permanently delete the specific image build
docker rmi the-movie-site:latest

# Clean up only the specific BuildKit builder caches created by this image
docker builder prune --filter "parent=the-movie-site:latest" --force
```

## Production Deployment Best Practices

Follow this structured blueprint to launch **the-movie-site** efficiently in a production environment:

### 1. Required Image Optimization

Next.js requires the native `sharp` library to efficiently process and resize graphics (posters, backdrops, etc.) in a production container. Ensure it is explicitly installed inside the standard dependencies before building:

```bash
npm install sharp
```

_Verify that `"sharp"` lands inside the `"dependencies"` block of the `package.json` rather than `devDependencies`._

### 2. Launch the Production Daemon

Deploy the container in detached background mode (`-d`) with automated recovery configurations to ensure high availability:

```bash
docker run -d \
  --name the-movie-site-prod \
  --restart unless-stopped \
  -p 80:6969 \
  -e NODE_ENV=production \
  the-movie-site:latest
```

### 3. Production Resource Monitoring

To view logs or check the runtime resource usage of the running production site:

```bash
# View live application logs
docker logs -f the-movie-site-prod

# Check memory and CPU usage
docker stats the-movie-site-prod
```
